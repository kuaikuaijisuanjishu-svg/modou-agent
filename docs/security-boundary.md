# 本地安全边界

展示包面向评委在自己的计算机上运行。它不是托管服务，也不会把评委仓库上传到展示仓库。

## 输入边界

- 评委通过命令行明确指定允许审查的本地仓库。
- 测试路径必须是仓库内的相对路径。
- 服务绑定 `127.0.0.1`，浏览器请求需要本次启动生成的令牌。
- `trusted_local` 模式只适用于评委信任的仓库；需要更强隔离时使用 `sandboxed` 模式。

## 证据边界

对外 ReviewBundle 只保留复核所需的结构化摘要。公开导出会处理以下内容：

- 主机用户名、绝对路径和编码后的临时目录路径；
- 源码行、完整文件内容和测试命令输出；
- 原始模型响应、提示词和模型私有 trace；
- 本地仓库 ID、运行 ID、交付 ID 和 UUID；
- 模型服务 URL、令牌、密码和其他凭据形状。

保留下来的字段用于说明执行模式、测试结果、恢复状态和摘要完整性，不包含内部开发过程。

## 发布边界

发布前运行 `python tools/public_release_check.py`。如果检查失败，不应将目录提交或推送到公开仓库。

公开仓库只接受两类 ref：`main` 分支与 `v*` 发布标签。集成分支、研究工作树和内部候选版本不进入公开 refs。推送纪律在客户端按两个维度拦截：ref 名称，以及被推送的树是否含研究目录——含研究目录的树即使推向 `main` 也会被拒绝。

GitHub 侧启用 Secret Scanning 与 Push Protection。`main` 的每次推送和每个 `v*` 标签都由工作流复核同一组公开检查，标签还会额外重跑完整发布门禁。
